# project

2026-08-09, whole-project Radix -> Base UI migration of `packages/ui` (13
wrappers) and their `apps/desktop` call sites.

## Changed

Dependency swap, in `packages/ui/package.json` :
- added `@base-ui/react` `^1.7.0`
- removed `radix-ui` `^1.4.3`, after the last wrapper was migrated
- `pnpm-lock.yaml` regenerated by pnpm (the workspace's own package manager)

Style flip : `packages/ui/components.json` and `apps/desktop/components.json`
both move `"style": "radix-mira"` -> `"base-mira"`, so a future `shadcn add`
delivers Base UI variants instead of radix ones. This was done once, at the end,
rather than up front.

Wrappers migrated, one commit each, in dependency order (see the per-component
files for detail) :
`button` + `badge` + `label` (leaves, with the `pagination` and `alert-dialog`
Button call sites) -> `checkbox` + `switch` + `progress` + `scroll-area` ->
`accordion` + `popover` -> `alert-dialog` -> `select` -> `dropdown-menu` ->
`dialog`.

Strategy per file : the project's wrappers turned out to be the CLI-resolved
`radix-mira` registry files (IconPlaceholder resolved to lucide, `"use client"`
stripped, `@ptt/ui/*` imports). Normalizing both goldens the same way reduced 7
of 13 to a zero-line diff, so those were golden-pair three-way merges with
nothing to replay. `select` and `dropdown-menu` took the `base-mira` golden
directly (their only real deviation was stripped `cn-*` hooks, re-stripped on
the target). `dialog` was the exception : 65 lines of genuine customization, so
the transformation engine was applied to the project's own file instead, and its
`size` / `closable` props, custom close button and header/footer classes are
untouched.

App-code sweep, `apps/desktop` (the full `consumer-props.md` token list plus
`asChild` was grepped across `apps`, `packages` and `games`) :
- `converter/ProgressModal.tsx:83` : `<Accordion type="multiple">` -> `multiple`
- `converter/ProgressModal.tsx:132` : `onPointerDownOutside` / `onEscapeKeyDown`
  -> a single `onOpenChange(open, eventDetails)` that cancels on reason
  `'outside-press'` / `'escape-key'` while a job runs
- `Header.tsx:43` : `position="popper"` -> `alignItemWithTrigger={false}`
- `converter/SourceLanguage.tsx:28` : `value as LanguageCode` -> a `null` guard,
  because `onValueChange` now yields `LanguageCode | null`
No other call site needed a change : no `asChild` outside `packages/ui`, and
every `onCheckedChange` / `onValueChange` handler was already single-argument.

Final state vs the baseline (both taken with the same commands) :
- `pnpm typecheck` : 18/18 tasks, same as baseline
- `pnpm build` : 2/2 tasks, renderer bundle builds
- `pnpm test` : 18/18 tasks
- the repo's own bundle invariant still holds :
  `grep -c ZodError apps/desktop/out/renderer/assets/index-*.js` returns 0
Each commit also passed the repo's lefthook pre-commit gate (oxlint + full
turbo typecheck), so every commit in the series is independently green.

**0 wrappers remain on Radix** in `packages/ui/src/components/`.

  touched were formatted. `packages/ui` is excluded from oxfmt anyway.

## Behavior changes

Collected from the per-component files; none of these was silently patched.
- `alert-dialog` : `AlertDialogAction` no longer closes the dialog (Base UI has
  no Action part). No consumer yet.
- `dropdown-menu` : `closeOnClick` defaults to FALSE on checkbox and radio
  items, where radix closed the menu on select. No consumer yet.
- `button` : `data-variant` / `data-size` are no longer emitted.
- `scroll-area` : the radix `type` prop is gone; scrollbar visibility is now
  Base UI's default rather than an explicit choice.
- `popover` : `PopoverAnchor` is removed (no Base UI equivalent).
- `select` : `onValueChange` can deliver `null`.
- `accordion` / `toggle-group` style APIs : `value` / `defaultValue` are always
  arrays now.
